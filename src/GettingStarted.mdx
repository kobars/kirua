# Getting started

Run kirua locally, explore a working screen, then inspect its components.
The package is private and has no published installation flow yet.

## 1. Start the workspace

Use Node `^20.19.0 || ^22.12.0 || >=24.0.0` and pnpm 10.

```bash
git clone https://github.com/kobars/kirua.git
cd kirua
pnpm install
pnpm storybook
```

Open **http://localhost:6006**. The component docs include live previews, source
and props. Open a story to change its controls, colour mode or containing surface.

## 2. Open the example app

The example app holds five applications as sections — a marketing site, a shop,
a social app, a hospital system and an assistant — and a hub that links to them:

```bash
pnpm example
```

Open the URL Vite prints. Each section's routes start with its name, such as
`#/shop/` or `#/his/patients`, and each section loads only its own code. Data
and actions are local demos.

## 3. Compose with the local aliases

Within the example app, `kirua` points to `src/components/index.ts` and
`kirua/styles.css` points to the app's stylesheet. These aliases are configured
in `examples/vite.config.ts`; they are not installed packages.

```tsx
import { Button, Card, CardBody, CardTitle, Field, Input } from 'kirua';
import 'kirua/styles.css';

export function NewsletterForm() {
  return (
    <Card padding="md" className="max-w-md">
      <CardTitle as="h2">A little inspiration each week</CardTitle>
      <CardBody>Drawing prompts and new work from the community.</CardBody>
      <form action="/subscribe" method="post" className="flex flex-col gap-4">
        <Field controlId="newsletter-email" label="Email address" required>
          <Input type="email" name="email" autoComplete="email" />
        </Field>
        <Button type="submit">Subscribe</Button>
      </form>
    </Card>
  );
}
```

The `/subscribe` endpoint is an application responsibility. For a working local
form with validation and confirmation, open
[Everyday screens](?path=/docs/patterns-everyday-screens--docs).

Each Field needs a unique `controlId`. It connects its child to the label,
description and error. The application decides when to validate and passes
`error` when there is a message to display.

## 4. Load the base typefaces

The host document loads the fonts; the component stylesheet does not fetch them.
Place these links in the document head, or self-host equivalent font files:

```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link
  rel="stylesheet"
  href="https://fonts.googleapis.com/css2?family=Luckiest+Guy&family=Nunito:wght@400..800&display=swap"
/>
```

Use display type for short promotional headlines. Use the text family for
navigation, labels, forms and reading. Both have system-font fallbacks.

## 5. Choose mode and surface

Set the `dark` class on `<html>` for dark mode. Read
[Dark mode](?path=/docs/foundations-dark-mode--docs) for initial paint and stored preferences.

Use `Card variant="brand"` or `Card variant="dark"` for a local contrasting panel.
A surface context affects inherited tokens; a portalled overlay inherits from its
portal container. Set the document mode on `<html>` so body-level portals receive it.

## State and server rendering

Static components can render on the server. Interactive Radix primitives carry
client boundaries and require JavaScript. Event handlers and hooks belong in your
application's client component when using React Server Components.

- **Field** displays your validation state; it does not validate or submit data.
- **Combobox** needs filtering, open state, keyboard navigation and selection.
- **Command** needs search, keyboard navigation, execution and a trigger.
- **Carousel** scrolls natively; your client code supplies previous/next controls.

Their Storybook pages include examples of the application code involved. Server
rendering is tested locally, but a complete framework integration is not yet verified.

## Useful component conventions

Import parts by name, such as `CardTitle` and `DialogContent`. Use `asChild` on a
Button when its action is navigation, passing an anchor with a real destination.
Provide `aria-label` for IconButton. Pick heading levels for the document outline
with `as`; choose their visual scale separately.

Use `className` for layout adjustments. Use existing variants and colour roles
for appearance. Set `dir="rtl"` on a container to exercise logical direction.
