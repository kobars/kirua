# Dark mode

The palette has a light mode and a dark mode, and dark mode comes in five night
palettes. Set the `dark` class on `<html>` to select dark mode; semantic colour
roles update throughout the document, including overlays that portal to the body.

```js
document.documentElement.classList.toggle('dark', true);
```

## Choose a night

A shadow reads as shade only when it is darker than the page, so a dark page
cannot sit at black: each night lifts its page off black and keeps a darker
shade below it, which every card, button, field and overlay casts. The shapes
are the same in both modes; only the colours change.

| Night      | Character                                            |
| ---------- | ---------------------------------------------------- |
| `navy`     | The default. Plain `.dark` gives it.                 |
| `graphite` | A nearly neutral cool grey over a pure black shade.  |
| `onyx`     | Pure neutral grey, darker than graphite.             |
| `ink`      | Navy's hue at half its chroma, so not a second blue. |
| `carbon`   | The darkest page, with a larger step up to the card. |

Set `data-night-palette` on the same element as `.dark` to choose one; remove it
for navy. It does nothing in light mode, so a choice can be stored and kept
while the page is light.

```js
document.documentElement.dataset.nightPalette = 'graphite';
delete document.documentElement.dataset.nightPalette; // back to navy
```

Every night fills the same seven roles — shade, sunken, page, card, hover, line
and strong line — and every text, field and chart pair is measured on each one.
[Colour](?path=/story/foundations-colour--night-palettes) shows them with live
ratios. To show a night's colours outside dark mode, such as a swatch in a
menu, put `data-night-swatch="<night>"` on the element and read
`--color-night-page` and `--color-night-raised` inside it.

## Set the initial mode before paint

Put this inline script in the document head before stylesheets. It reads an
explicit preference first, then falls back to the operating system. If browser
storage is unavailable, the system preference still works.

```html
<script>
  (() => {
    let preference;
    try {
      preference = localStorage.getItem('kirua-theme');
    } catch {
      preference = null;
    }
    const dark =
      preference === 'dark' ||
      (preference !== 'light' && matchMedia('(prefers-color-scheme: dark)').matches);
    document.documentElement.classList.toggle('dark', dark);
  })();
</script>
<script>
  (() => {
    const nights = ['navy', 'graphite', 'onyx', 'ink', 'carbon'];
    let night = 'navy';
    try {
      const stored = localStorage.getItem('kirua-night-palette');
      if (nights.includes(stored)) night = stored;
    } catch {}
    if (night !== 'navy') document.documentElement.dataset.nightPalette = night;
  })();
</script>
```

The night is a script of its own, so a theme script that throws on refused
storage cannot stop it.

If your host enforces a Content Security Policy, authorise the inline script
through its nonce or hash mechanism. In a framework, integrate this with the
host's document and hydration setup. A complete Next.js integration is not
currently exercised by this repository's checks.

## Let the user choose

An application can offer **Light**, **Dark** and **System**. Save explicit choices
under `kirua-theme`; remove the key for System. Apply the choice immediately and,
while System is selected, listen for changes to the colour-scheme media query.
Offer the night beside it, saved under `kirua-night-palette`, with navy removing
the key.

The example app keeps this flow in `examples/shared/useTheme.ts` and
`examples/shared/useNightPalette.ts`. Those hooks are application code and are
not exported as part of kirua. The theme hook assumes storage is available;
hosts with restricted storage should handle read and write failures.

The token stylesheet does not select dark mode with a media query. Keeping the
selection in the host lets an explicit Light choice override a dark system preference.

## Mode is different from a local surface

Use a brand or dark Card for a contrasting panel within a page. Its context
changes inherited roles locally. A body-level portal does not inherit the
trigger's local context; use a supported `container` prop when an overlay must
stay within that context.

## Preview in Storybook

Change **Mode** in the toolbar to switch the Storybook interface, documentation
page and example documents together, and **Night** to choose the night palette
dark mode uses. Each preview sets the class on its own
`<html>`, so body-level menus, dialogs and tooltips receive the selected mode too.

Storybook rebuilds the docs page when toolbar globals change, which resets
embedded examples. Open an individual story when you want to switch modes while
keeping an interaction, such as an open dialog, in progress.

The **Surface** control changes only the specimen's containing surface. A brand
panel within a dark page is still a brand panel. Stories explicitly comparing
fixed modes, such as Anime Hero's Light and Dark examples, retain their declared
mode; they do not change the surrounding documentation's selection.

See [Design direction](?path=/docs/design-direction--docs) for how future palettes
and styles relate to these two modes.
