# kirua

An expressive React design system for anime-inspired websites, social spaces and
everyday applications. Start playful, then choose how much personality a screen needs.

The base style combines vivid blue, rounded controls, friendly text and bold
display type. Corner glints and oversized artwork are optional accents. Forms,
feeds and checkout screens can use the same components with quieter surfaces.

## One base, different settings

A creator landing page can use a display heading, a brand panel and ornament.
A shop can reserve those accents for its campaign and keep product information
on neutral cards. A social feed can give content the space while using the brand
colour for its primary action.

These are different compositions of the current base. Multiple named styles,
additional palettes and packaged templates are the direction, not shipped APIs.

## How appearance adapts

A brand Card establishes a local surface context. Its children read colour roles
for that surface, so the primary action stays legible:

```tsx
import { Button, Card, CardTitle } from 'kirua';

<Card variant="brand" padding="md">
  <CardTitle as="h2">Your next drawing starts here</CardTitle>
  <Button>Join the club</Button>
</Card>;
```

The **Design direction** guide explains how this differs from a complete theme.
The **Surface contexts** foundation shows the actual token behaviour.

## Behaviour and accessibility

Radix Primitives provides behaviour for controls such as dialogs, menus and tabs.
kirua supplies their appearance. Applications supply data, validation and actions;
Combobox and Command also require application-owned keyboard and selection logic.

Automated checks exercise component stories, contrast and selected interaction
paths. Raw-token foundation specimens include exceptions to axe checks. Review
complete screens with a keyboard and assistive technology as well.

## Project status

kirua runs from source and is not published to npm. There is one base style with
light and dark modes. No reuse licence is currently supplied, and the hero's
third-party character assets need separate permission or replacement.
