# kirua

A React design system with a three-layer token architecture, built on
[Radix Primitives](https://www.radix-ui.com/primitives). 74 components, all
server-renderable, all tested against WCAG 2.1 AA.

This Storybook **is** the documentation. Every component has a page, every
foundation has a page, and every number quoted on those pages is computed in the
browser from the tokens that actually ship.

## The idea in one example

Colour is decided by the surface a component sits on, not by a prop it is passed.

```tsx
<Button variant="primary">Get started</Button>

<div className="ctx-brand bg-brand">
  <Button variant="primary">Get started</Button>
</div>
```

The first renders as a blue pill on a white page. The second renders as a white
pill on the brand panel. Same component, same props, no override, no `inverted`
prop, no theme provider.

A surface declares its context with a class, and every semantic token inside that
subtree is re-pointed for the whole tree below it. Dark mode is the same
mechanism: one block of re-pointed variables and zero component changes.

Use the **Surface** and **Mode** controls in the toolbar above to put any story
on any surface, in either mode, without editing it.

## How the tokens are layered

```
tokens.primitives.css   @theme          raw values      blue-500 = #0A84FF
        ↓
tokens.semantic.css     :root / .ctx-*  meaning         surface-brand = blue-600
        ↓
theme.css               @theme inline   utility alias   bg-brand → surface-brand
        ↓
components                                              <Card variant="brand">
```

Components read the **semantic** layer only. They never reference a primitive and
never a raw hex. That indirection is what turns a theme change into a variable
change instead of a component change.

`@theme inline` is load-bearing rather than stylistic. It compiles utilities to
literal `var(--color-…)` references instead of freezing the value at build time,
which is what allows a context switch to propagate at runtime.

## Colour and contrast

The reference design's brand blue is `#0A84FF`. White body copy on it measures
**3.65:1**, and at the reference's own 80% opacity it measures **2.85:1**. WCAG
AA requires **4.5:1** for body text.

That is not fixable per component, so the system separates two blues:

- **`blue-500`** — `#0A84FF`, the identity blue, kept exact. Used behind display
  type, where AA Large's 3:1 threshold applies.
- **`blue-600`** — `#0973DC`, the text-bearing surface. Measures **4.67:1**
  against white.

`--color-surface-brand` points at `blue-600`, and every component inherits it.

Every ratio above is recomputed in the browser on **Foundations → Colour**, so
these pages cannot drift from the CSS.

## Behaviour comes from Radix

Dialog, DropdownMenu, Tooltip, Select, Tabs and the rest are built on Radix
Primitives — headless components that supply behaviour and accessibility and no
appearance at all.

That split is why this system can look nothing like a default component library
and still trap focus correctly, restore focus to the trigger, support typeahead
in a menu, and move through tabs with the right keyboard model.

## Every component is stateless

No component here calls a hook or carries a `"use client"` directive, so a Card
inside a React Server Component ships no JavaScript to the browser at all. A test
asserts this rather than a convention remembering it.

The trade-off is worth stating: `Combobox`, `Command` and `Carousel` are
**presentational shells**. They render the right elements with the right ARIA
wiring, and the consumer owns the open state, the filtering and the current
index from their own client component. A component that filtered its own list
would be smaller to use and impossible to server-render.

## Accessibility is enforced, not reviewed

Every story on this site runs axe with violations set to **error**, so an
accessibility failure fails the build rather than printing a warning. Beyond
that, dedicated test runs cover Windows high contrast, `prefers-reduced-motion`,
target size under WCAG 2.5.8, and both reading directions.

## The reference design

The values marked `[FIGMA]` in the CSS are measured from *Figma Anime Website UI
Design: Futuristic & Interactive Hero Section*, published on Figma Community.

The reference is one desktop marketing frame: about twenty loose shapes, no
components, no variables, no styles. It has no form fields, no tables, no modals,
no hover, focus, disabled, loading, empty or error states, no mobile layout and
no dark mode. Everything unmarked was designed to fill the gaps a single screen
leaves, and the marking makes the difference visible everywhere it matters.
